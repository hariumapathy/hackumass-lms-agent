# RAG and sync audit

Planning evidence from `main` at `be13793`, inspected 2026-11-23. No application code was changed, production data inspected, platforms called, or performance benchmark run for this audit. Findings below are code-confirmed behavior or explicitly marked hypotheses. Proposed schema/interface changes need review before implementation.

## What is already solid

The assistant reads a user-scoped database abstraction; platform access stays in the worker. Search combines vector and full-text candidates with reciprocal-rank fusion, with fixed SQL fragments and bound values (`backend/app/db/repositories/agent.py:126`). HNSW, full-text GIN and user/course/current indexes already exist (`supabase/migrations/0001_init.sql:302`); this is not a missing-vector-index problem.

Chunks retain source page/time references. New chunk versions are published transactionally, and unchanged extracted text avoids another embedding call (`backend/app/sync/processing/process.py:184`). Citation IDs must have been returned by tools in the current run, and quoted passages receive a fuzzy check (`backend/app/agent/citations.py:66`). Tests cover owner isolation, version preservation after embedding failure and several connector edge cases; they are useful regression foundations, not evidence of load capacity.

Identical open sync scopes are deduplicated under a Postgres advisory transaction lock (`backend/app/sync/jobs.py:197`). Canonical merges themselves are serialized per user and transactional (`backend/app/sync/merge.py:601`). Preserve these protections rather than replacing the queue or retrieval stack wholesale.

## Findings and launch priority

P0 means resolve before a hosted student pilot; P1 means required for dependable operation/budget control, generally before expanding the pilot. Ordering emphasizes correctness before speed.

| ID | Priority | Verified finding and consequence | Evidence / proposed correction |
|---|---|---|---|
| RS01 | P0 | New searches can return chunks whose parent material/post was removed. Search requires `ch.is_current`, but does not exclude removed parents. The SQL computes a status field, yet the read-tool chunk serializer omits it, so the model does not receive that warning. Historical citations should remain resolvable; new retrieval needs a stricter eligibility rule. | `db/repositories/agent.py:38`, `:140`, `:167`; `agent/tools/read.py:78`. Separate historical citation resolution from current retrieval; exclude removed parents, explicitly label stale fallback versions. |
| RS02 | P0 | Canvas file caps return without declaring the materials listing incomplete. On a full sync, absent previously stored files can therefore be marked removed. Module fallback has the same cap exit; an individual inaccessible module file is skipped without marking the listing incomplete. | `connectors/canvas/connector.py:225`, `:247`; `sync/pipeline.py:336`, `:441`. Record per-resource listing completeness and only infer removals from authoritative complete listings. Test cap boundaries, permission changes and pagination failure. |
| RS03 | P0 | Reappearing unchanged item sources/posts/materials do not restore their status from removed: the unchanged branches call `touch`, which only updates freshness. Restored identical content can stay removed indefinitely. | `sync/pipeline.py:134`, `:202`, `:255`, `:311`. Make presence restoration an explicit state transition; keep it distinct from content changes and alert semantics. |
| RS04 | P0 | Sync commits each record before the entire fetch finishes. Processing jobs are collected in memory and deferred only on success. If a later fetch fails, earlier records stay stored but their chunks may never be queued; the next successful sync sees identical hashes and does not add them to the processing list. A crash between commit and defer has a similar gap. | `sync/pipeline.py:420`, `:434`, `:461`; `sync/jobs.py:166`. Use a transactional processing outbox or durable dirty-generation marker and reconciliation job. Do not make full-import success the only route to indexing committed content. |
| RS05 | P0 | Exhausted embedding/Storage failures in material processing fall through the broad exception handler, set processing status failed and return normally. The queue task does not inspect that outcome, so it can finish successfully without a retry. Posts have no configured retry policy. Ordinary unchanged syncs do not repair either path. | `sync/processing/process.py:238`, `:272`; `sync/jobs.py:130`, `:147`; `sync/pipeline.py:434`. Classify retryable provider/Storage errors, persist attempts/backoff, and reconcile failed/pending/stuck processing. Keep old chunks available with truthful stale status. |
| RS06 | P0 | Sync execution is not serialized across overlapping scopes. Deduplication locks include the exact scope and end before worker execution, while writes/removal detection occur across transactions. A full sync and course sync can overlap; merges have their own lock rather than a shared ingestion generation. | `sync/jobs.py:211`, `:77`; `sync/pipeline.py:420`; `sync/merge.py:606`. Define per-user/platform execution ownership, record generations/checkpoints, and compare-and-swap publication. Prove races before choosing the smallest lock scheme; do not assume queueing locks serialize running work. |
| RS07 | P0 | Embedding provenance is a comment rather than an enforced invariant. Chunk rows contain only a fixed 1536-dimensional vector, with no provider/model/task/configuration identity. Unchanged-text optimization will skip re-embedding when settings change. Fake and real vectors, or future models with the same dimension, can be silently mixed. | `core/embeddings.py:1`, `:19`, `:105`; migration `0001_init.sql:169`; `sync/processing/process.py:188`. Add an index/embedding generation identity, production refusal of fake mode, migration/backfill tooling and atomic cutover. Changing chat models alone should not force a retrieval re-embedding. |
| RS08 | P1 | After retry exhaustion a transient sync error sets connection status error, but the scheduler scans only active connections. It therefore does not automatically revisit that connection after the external outage ends. | `sync/pipeline.py:454`; `sync/jobs.py:263`. Separate health from authorization: retry recoverable errors with backoff/circuit breaking; stop only for explicit disconnect/auth expiry. |
| RS09 | P1 | Token counts and model request counts are captured in memory but not persisted by the DB store; the `agent_runs` table has no usage/cost columns. Turn/time limits and a process-local request bucket are not durable student spending limits. | `agent/runtime.py:319`; `agent/db_store.py:71`; `db/repositories/chat.py:123`; migration `0001_init.sql:222`; `core/ratelimit.py:1`. Add a durable usage ledger, per-user/global budget reservation and reconciliation, output-token limits and concurrency limits. Count retries, embeddings and ingestion too. |
| RS10 | P1 | Twelve history messages is a count limit, not a token budget. The DB loads all conversation messages before slicing. A single tool result can be 24,000 characters; multiple retrieval calls accumulate in the model run. Current model settings only request usage reporting. | `db/repositories/chat.py:87`; `agent/runtime.py:52`, `:145`, `:159`, `:255`; `agent/tools/results.py:9`. Bound the SQL history fetch, then enforce input/context/output budgets. Compact history with retained citation provenance; diversify overlapping retrieved chunks and avoid duplicate tool outputs. |
| RS11 | P1 | Posts are wrapped as untrusted data, but PDF/page/slide/transcript text and metadata remain plain tool content. Citation validity proves membership/quote similarity, not that a claim is actually supported. Invalid citations are removed from final text without removing or correcting their unsupported claim. Text is streamed before final validation. | `agent/tools/read.py:78`; `agent/tools/results.py:60`; `agent/citations.py:66`; `agent/runtime.py:183`, `:339`. Treat all synced content as untrusted, keep tools constrained, test adversarial materials and show evidence limits. Define UI handling of unverified streaming text and invalid final evidence. Do not market this as semantic fact verification. |
| RS12 | P1 | Piazza skips full posts based on the platform-wide last successful sync, rather than a per-post stored version. A class newly joined after an earlier sync can have older posts skipped. Skipped malformed posts are also not retried if their timestamp stays older than the cursor. | `connectors/piazza/connector.py:96`; `sync/pipeline.py:412`. Store per-class/per-item checkpoint state or known hashes; give new connections/classes a bounded initial backfill and use overlap windows. |
| RS13 | P1 | `fetch_latest` waits sequentially per platform while holding one borrowed connection. Three platforms can consume up to three separate 15-second waits despite a 25-second outer tool timeout. It also waits on source sync completion rather than canonical merge/index readiness. | `agent/tools/db_source.py:119`; `agent/runtime.py:56`; `sync/jobs.py:120`; pool `db/pool.py:24`. Use one overall deadline, concurrent bounded waits without holding a connection between polls, and distinguish imported / organized / searchable readiness. |
| RS14 | P1 | First-origin Canvas downloads receive the bearer token for whatever URL the connector supplied. Redirect stripping does not itself validate that first destination or protect against internal URLs. | `sync/processing/storage.py:150`. Treat this as a trust-boundary review: allowlist authenticated Canvas origins, validate redirect/download destinations and private-address targets, and sandbox document extraction. Do not infer exploitability without a controlled test. |

## Cheap improvements after correctness

These are opportunities, not measured bottlenecks. Instrument first and keep the existing architecture unless measurements justify a change.

- Cache query embeddings by normalized query + embedding identity with a bounded TTL. Cache retrieved results only with user ID, selected courses, permissions and index generation in the key. Never share private result/answer caches across students. `DbToolData.search` currently embeds every call (`agent/tools/db_source.py:81`).
- Reuse HTTP connection pools for embedding calls and Storage requests. `GeminiEmbeddings.embed` creates/closes a client when none was supplied (`core/embeddings.py:93`), and Storage does likewise per request (`sync/processing/storage.py:59`). Measure handshake overhead before changing lifecycle ownership.
- Batch chunk inserts rather than one SQL round trip per chunk (`sync/processing/process.py:110`), and cache embeddings by normalized chunk content plus embedding identity inside a user's access boundary. Re-embed only changed chunks; publish the complete document generation atomically.
- Avoid loading all items/chunks for Python-side date/page filters (`agent/tools/read.py:108`, `:176`); push bounded predicates/limits to SQL. `get_course_overview` fetches the same course items twice (`:203`). Use request-local course/connection caches with explicit invalidation after refresh.
- Separate interactive merge/metadata capacity from bulk extraction/embedding capacity. The single worker listens to both queues with concurrency four (`cli.py:92`). Keep fair per-student/provider limits and add jitter, rather than allowing one large initial import or synchronized 5-minute scheduler sweep to monopolize capacity.
- Bound retention for historical chunks, raw job payloads and sync-run history; account for citation retention before deleting old versions. Avoid cross-student deduplication of private materials without an explicit permissions and deletion design.

## Performance hypotheses that require experiments

1. The global HNSW index plus restrictive user/course filters may underfill candidate lists or lose recall for small tenants. Compare to exact per-tenant search on the installed pgvector version with `EXPLAIN (ANALYZE, BUFFERS)`. Tune candidate count/search settings only after recall measurements. Do not partition or buy another vector database by default.
2. Fixed similarity floor 0.2, 30 candidates and character-based output truncation may be poor for terse course-specific questions. Measure Recall@k and citation support before adding a reranker, semantic cache or larger context window.
3. PDF parsing/chunk tokenization runs synchronously within async processing. CPU-heavy or decompression-heavy files may block a worker's event loop. Measure then isolate parsers with CPU/memory/time budgets in a bounded process pool or dedicated workers.
4. Merge loads the student's complete item/source history and scans candidates in Python (`sync/merge.py:376`, `:444`); scheduled complete imports may become expensive across several semesters. Measure query count/CPU before introducing dirty-course merges and indexed matching.
5. Freshness currently reports successful source fetch time, not successful searchable generation publication. Measure ingest-to-query-ready lag separately; an apparently fresh connection can still have failed or queued material processing.

## Proposed design and implementation order

No task here is approved for coding yet. Each should become a Ready spec with design review, migration/API proposal if needed, failing tests, implementation, checks and its own commit.

1. **Correctness and recovery:** RS01–RS06. Define source presence states, complete-listing guarantees, publication generations, idempotency and an outbox/reconciler. Keep tenant boundaries explicit. Add crash/retry/concurrency regression fixtures before refactoring storage.
2. **Embedding lifecycle:** RS07. Select one retrieval embedding configuration for the pilot; add provenance and safe backfill/cutover. Keep chat-provider routing independently configurable.
3. **Hosted cost and availability:** RS08–RS10, RS13. Durable quota/usage accounting, retry classification, one-deadline refresh, SQL bounds and stream failure handling. Export latency/queue/usage metrics without message text or credentials.
4. **Evidence and attack resistance:** RS11–RS12, RS14. All-source untrusted treatment, checkpoint repair, citation support evaluation, constrained downloads/parsers. Coordinate with deployment/security audit.
5. **Measured optimization:** run the benchmark below, then select only changes supported by results. Keep a rollback generation and compare quality/cost to the same frozen baseline.
